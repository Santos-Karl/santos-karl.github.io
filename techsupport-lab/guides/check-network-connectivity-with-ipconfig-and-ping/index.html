Check network connectivity with ipconfig and ping

A layered method to find out whether a Windows PC has a bad address, a bad gateway, bad DNS, or no internet at all.

Overview

When a PC says it is connected but websites do not load, test each layer in order: the local address, the gateway, a public IP address, and then a name lookup. The first layer that fails tells you where to look next.

Symptoms

  • Wi-Fi or Ethernet shows connected, but web pages do not load.
  • Some apps work while others fail.
  • A browser shows a DNS error such as 'server not found'.

Possible causes

  • A 169.254.x.x (APIPA) address: the PC did not receive an address from DHCP.
  • Wrong default gateway, or the router is offline.
  • DNS server is unreachable or misconfigured.
  • The ISP or modem is down.

Requirements

  • A Windows PC (Windows 10 or 11).
  • Standard user rights are enough for these commands.

Step-by-step instructions

  1. Open Command Prompt and run ipconfig. Note the IPv4 address, subnet mask, and default gateway.
  2. If the address starts with 169.254, renew the lease (see the commands below) and check the router's DHCP setting.
  3. Ping the default gateway. If this fails, the problem is on the local network.
  4. Ping a public IP address such as 8.8.8.8. If this works but names fail, the problem is DNS.
  5. Run nslookup for a well-known name. If it fails, try a different DNS server or flush the cache.
  6. Record which step failed and what you changed, then retest from step 1.

Troubleshooting notes

  • A ping reply proves the path works at that moment. It does not prove firewalls allow every port.
  • Some networks block ICMP (ping). If ping fails everywhere but browsing works, test with a web request instead.

Common mistakes

  • Changing DNS settings before checking whether the gateway responds.
  • Running ipconfig /release on a remote session without warning the user, because the connection drops.

Security and safety warnings

  • Do not change network adapter settings on a corporate or school network without permission.
  • ipconfig /release drops the connection until /renew completes. Do this locally or with a plan to reconnect.

Verification steps

  • ping 8.8.8.8 succeeds and nslookup returns an address for a known site.
  • A web page loads in a browser after the fix.

Commands

ipconfig

Shows the IPv4 address, subnet mask, and default gateway for each adapter.

Example output (typical, will vary)

IPv4 Address. . . . . . . . . . . : 192.168.1.42
Subnet Mask . . . . . . . . . . . : 255.255.255.0
Default Gateway . . . . . . . . . : 192.168.1.1
ping 192.168.1.1

Tests whether the default gateway answers. Replace the address with your gateway.

Example output (typical, will vary)

Reply from 192.168.1.1: bytes=32 time=2ms TTL=64
ping 8.8.8.8

Tests internet reachability by IP address, which skips DNS.

Example output (typical, will vary)

Reply from 8.8.8.8: bytes=32 time=14ms TTL=117
nslookup www.microsoft.com

Asks the configured DNS server to resolve a name.

Example output (typical, will vary)

Server:  dns.example.local
Address:  192.168.1.1
Non-authoritative answer:
Name:    www.microsoft.com
ipconfig /flushdns

Clears the local DNS resolver cache. Safe to run; no settings change.

Example output (typical, will vary)

Successfully flushed the DNS Resolver Cache.
ipconfig /release
ipconfig /renew

Releases the current DHCP lease and requests a new one. Briefly drops the connection.

Example output (typical, will vary)

Windows IP Configuration

Ethernet adapter Ethernet:
   IPv4 Address. . . . . . . . . . . : 192.168.1.42
