Lab: reset a password and unlock an account in Active Directory

Practice the two most common help desk tasks: unlocking an account and resetting a forgotten password.

Overview

LAB practice only. Always confirm the caller's identity through the approved process before changing a password, even in an exercise, so the habit starts early.

Step-by-step instructions

  1. Verify identity using the approved callback method.
  2. Check the account status and lock state (see the command below).
  3. If the account is locked, unlock it.
  4. Reset the password and set Change Password at Next Logon.
  5. Record the time, the reason, and who approved the change in the ticket.

Common mistakes

  • Resetting a password before confirming who asked.
  • Unlocking an account without checking which device caused the lockout.

Security and safety warnings

  • Lab only. Real password resets must follow the company identity check.
  • Never paste passwords into tickets or chat.

Verification steps

  • LockedOut is False after the unlock.
  • The user signs in with the temporary password and is asked to change it.

Commands

Get-ADUser -Identity lab.user1 -Properties LockedOut, Enabled

Read-only. Shows whether the account is enabled and whether it is locked.

Example output (typical, will vary)

Enabled        : True
LockedOut      : False
SamAccountName : lab.user1
Unlock-ADAccount -Identity lab.user1

Clears the lockout. Changes account state.

Example output (typical, will vary)

(No output on success. Run the read-only check again to confirm LockedOut is False.)
