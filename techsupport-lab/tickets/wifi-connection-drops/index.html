INC-0001

User cannot connect to Wi-Fi

Priority
Medium
Impact
One user, cannot work from the laptop until fixed.
Customer
Angela Cruz
Department
Accounting

Ticket description

My laptop shows Wi-Fi as connected but no websites load. It worked yesterday. I restarted it twice and nothing changed.

Contact: angela.cruz@example.com

Questions to ask

  1. Does the laptop show a Wi-Fi name, and is it the office network?
  2. Do other devices (phone, another laptop) work on the same network?
  3. Did anything change since yesterday, such as an update or a password change?
  4. Does an Ethernet cable connection work, if one is available?

Troubleshooting steps

  1. Run ipconfig and check the IPv4 address. A 169.254.x.x address means no DHCP lease.
  2. Ping the default gateway, then a public IP address such as 8.8.8.8.
  3. Run ipconfig /flushdns and ipconfig /release followed by ipconfig /renew.
  4. Forget the Wi-Fi network and reconnect with the current password.
Show model solution

Expected findings

  • IPv4 address is 169.254.x.x (APIPA), so the laptop did not get an address from the router.
  • Other devices on the same network work, which points to the laptop, not the router.

Resolution

  • Renew the IP lease and confirm the laptop gets a 192.168.x.x or 10.x.x.x address.
  • If the lease still fails, reset the network stack with netsh winsock reset and netsh int ip reset (administrator, restart required).

Documentation notes

Symptom, IP address before and after, commands run, and which device or step fixed the problem.

Escalation criteria

Escalate if other devices also fail (router or ISP issue) or if the network adapter is missing from Device Manager.

Sample ticket closure

Thanks for reporting this. The laptop was not receiving a network address. After renewing the address and reconnecting to Wi-Fi, browsing works. If it returns, please contact us so we can check the adapter driver.
